# コーディング規約

## 1. 言語とツール

| 項目 | 採用 |
| --- | --- |
| 言語 | TypeScript のみ（`.js` を書かない） |
| ビルド | Vite |
| 描画 | Phaser 3 |
| Lint/Format | Biome |
| テスト | Vitest（unit）、Playwright（e2e） |
| パッケージ管理 | pnpm |

## 2. テスト駆動開発（TDD）

### 2.1 適用範囲

| 層 | 方針 |
| --- | --- |
| `src/core/` | **TDD必須**。新しいロジックは「失敗するテスト → 最小の実装 → リファクタ」の順で書く |
| `src/balance/` | 定数表の変更は、その値を使うcoreのテストで担保する |
| `src/data/` | テスト対象外。型（`LocKey` 等）とデータ検証スクリプトで担保 |
| `src/phaser/` | TDDの対象外。E2Eと手動QAで確認する |
| `scripts/` | 「入力→出力の一致」を1本のテストで確認する |

- 試作（spike）は先に書いてよい。ただし採用する時点でテストを追加する。
- バグ修正は、**先に再現テストを書く**（赤を確認してから直す）。

### 2.2 サイクル

1. 振る舞いを1つ選び、日本語のテスト名で書く
2. 失敗することを確認する（赤）
3. 通る最小の実装を書く（緑）
4. 重複を除去する（リファクタ）。テストは緑のまま
5. 品質ゲートを実行してコミットする

### 2.3 単体テストの原則（『単体テストの考え方/使い方』準拠）

- **観測可能な振る舞いをテストする。** private メソッド、内部の呼び出し順、実装の都合をテストしない。
- **実装の詳細に依存しない。** リファクタでテストが壊れるなら、テストが詳細を見すぎている。
- **1テスト1振る舞い。** 複数の確認を1つのテストに詰めない。
- **AAA（準備・実行・確認）を構造で分ける。** 空行で3ブロックに区切る。
- **モックは外部境界のみ。** `localStorage`、時刻、外部I/Oは差し替える。core内部の協調オブジェクトは実物を使う。
- **テストは仕様書として読めること。** テスト名を並べただけで仕様が分かる状態にする。
- **失敗の原因が名前から分かること。** 「〜のとき〜になる」の形で書く。

### 2.4 テスト名

**日本語の自然言語で、振る舞いをそのまま書く。**

```ts
describe("ミスカウント", () => {
  it("誤答が上限に達するとゲームオーバーになる", () => {});
  it("上限未満の誤答ではゲームオーバーにならない", () => {});
  it("リトライすると0に戻る", () => {});
});
```

- 悪い例: `it("increment works")`、`it("テスト1")`、`it("should return 3")`
- 実装名を並べない（`it("addMiss を呼ぶ")` は実装依存）。
- E2Eも同じ方針（`test("ミス3回でゲームオーバー画面が出る")`）。
- 英語の識別子（関数名・型名）と日本語のテスト名を混在させてよい。

## 3. コメント

- **原則としてコメントを書かない。** 名前と構造で意図を表す。
- 例外: 外部仕様の出典（URL）、非自明な計算の根拠、回避策の理由。いずれも1行で書く。
- 変更履歴をコメントで残さない（git の役割）。
- テストの `describe` / `it` は、コメントの代わりに振る舞いを語る場所として扱う。

## 4. 型

- `any` 禁止。`unknown` + 型ガードを使う。
- `as` によるキャストは、外部データ（JSON）の境界のみ許可。
- 公開関数は戻り値の型を明示する。
- ユニオン型の網羅性は `switch` + `never` で担保する。

## 5. 状態

- 状態の変更は core のメソッド経由のみ。`state.missCount++` のような外部からの直接変更を禁止。
- グローバル変数、モジュールスコープの可変変数を使わない。
- 配列・オブジェクトは必要に応じてコピーして返す（呼び出し側で破壊的変更をしない）。

## 6. 非同期

- `async/await` を使い、Promise チェーンを書かない。
- アセット読込以外で `setTimeout` による待機を書かない（core は時間に依存しない）。
- core に `Date.now()` を持ち込まない。経過時間は引数で渡す。

## 7. ローカライズ

- 画面に出す文字を直書きしない。`t('key')` を経由する。
- キーは ja.json と en.json の両方に追加する。
- 数値・金額の整形は `formatCurrency` / `formatDate` 等の共通関数を使う。

## 8. 禁止事項

| 禁止 | 理由 |
| --- | --- |
| `src/core/` での Phaser / DOM import | レイヤ違反。headless テストが壊れる（DOM自体を使わない方針） |
| `window.localStorage` を core から直接触る | 保存は Repository 経由 |
| データに日本語文を直書き | ローカライズ不能になる |
| 乱数（`Math.random()`）の使用 | 決定性を壊す |
| `console.log` の残置 | デバッグは開発用フラグで制御 |
| 実装の詳細を確かめるテスト | リファクタで壊れ、仕様の保証にならない |

## 9. 品質ゲート

| コマンド | 基準 |
| --- | --- |
| `pnpm typecheck` | エラー0 |
| `pnpm lint` | 警告0（例外は設定で明示） |
| `pnpm test:run` | 全件成功 |
| `pnpm build` | 成功、バンドルサイズ警告なし |
| `pnpm test:e2e` | 主要動線が成功（preview 起動前提） |
| `pnpm docs:validate` | frontmatter とリンク切れなし |

ゲーム破壊的バグ（セーブ破損、遷移不能、ミス上限の誤判定）は**ブロッカー**として扱う。

## 10. コミット

- Conventional Commits: `feat:`, `fix:`, `docs:`, `refactor:`, `test:`, `chore:`。
- 1コミット1目的。ドキュメントのみの変更は `docs:` を付ける。
- TDDの赤→緑は1コミットにまとめてよい（赤だけのコミットを残さない）。
