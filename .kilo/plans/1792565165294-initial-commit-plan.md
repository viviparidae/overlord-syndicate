# コミットプラン

## 1. 概要
1990年代日本を舞台にした横スクロールADV × 社会侵食シミュレーションゲームの初期開発リポジトリに対する最初のコミット。すべての構成ファイル、ドキュメント、基本的なソースコード構造が含まれる。

## 2. コミットの目的
- Git ベースの管理を有効化
- プロジェクトの構成（言語、ビルド、テスト、linting、CI）を確立
- ゲームアーキテクチャと開発方針を文書化
- 継続的な開発のための基盤を提供

## 3. コミットで追加されるもの

### 3.1 プロジェクト構成ファイル

| ファイル | 目的 | 重要性 |
|---------|---------|----------|
| `README.md` | プロジェクトのドキュメント、コンセプト、ゲームシステム | 最初の印象と開発者のためのガイドライン |
| `package.json` | 依存関係管理、スクリプト、エンジン設定 | パッケージ管理とテスト/ビルドを有効化 |
| `pnpm-lock.yaml` | 正確な依存関係バージョン | 本番環境での再現性を保証 |
| `tsconfig.json` | TypeScript 設定とパスのエイリアス | 一貫した型チェックとモジュール解決 |
| `vite.config.ts` | Vite 構築と開発サーバー設定 | 超高速な開発環境を提供 |
| `vitest.config.ts` | Vitest テスト設定 | ヘッドレス環境でのテストを有効化 |
| `biome.json` | Biome linting 設定 | 一貫したコードスタイルを強制 |
| `kilo.json` | Kilo エージェント設定 | Kilo エージェントとワークフローを統合 |

## 4. コミットの課題

### 4.1 空のソースコード
- ソースコードはまだプロトタイプ段階（Phase 1 完了、Phase 2 準備中）
- 最初のコミットは基本設定を確立し、継続的な開発を可能にする

### 4.2 アーキテクチャの複雑性
- 厳格な関心分離ルール（core, phaser, ui, data, balance, localization）
- 複雑で成熟した設定システム

### 4.3 トレーサビリティの要件
- Front Matter CMS を使用する FOAM ドキュメント管理
- すべてのソースコード変更に対する実装と検証の追跡が必要

## 5. コミットの検証

### 5.1 コンプライアンスチェック
```bash
pnpm lint          # Biome コンプライアンス
pnpm typecheck     # TypeScript コンプライアンス
pnpm test:run      # Vitest コンプライアンス
cat package.json | grep "scripts"
```

### 5.2 コンテンツ検証
- すべての必須構成ファイルがコミットされていることを確認
- 構造が AGENTS.md ルールに準拠していることを確認
- トレーサビリティフィールドが frontmatter.json に定義されていることを確認

## 6. リスク

### 6.1 設定の不完全
- 不足した設定や不完全な設定が、将来の開発で問題を発生させる可能性がある
- すべての主要ツールのコンプライアンスチェックが必要

### 6.2 アーキテクチャの不一致
- 厳格なアーキテクチャ制約が、新規ファイルが正しい場所に配置されることを要求
- ソースコードはまだ不完全で、制約のテストが不可能

### 6.3 ドキュメントの遅れ
- トレーサビリティ要件がソースコード変更と同期する必要がある
- すべてのドキュメントが AGENTS.md のルールに更新される必要がある

## 7. 受け入れ基準

1. すべての主要構成ファイル（9 つ以上）がコミットされている
2. `pnpm lint` でエラーが 0 件（Biome）
3. `pnpm typecheck` でエラーが 0 件（TypeScript）
4. `pnpm test:run` で全テストが PASS し、`src/core/` のカバレッジが 80% 以上
5. `pnpm build` が成功し、`dist/` ディレクトリが生成される
6. `git status` で未追加の変更がない
7. ソースコードがアーキテクチャルール（src/、phaser、core、ui などのサブディレクトリ）に従っている
8. トレーサビリティデータが `src/core/` 変更の `implemented_by` フィールドに保存されている

## 8. テストカバレッジ目標

- `src/core/` ディレクトリ：80% 以上
- `src/phaser/` ディレクトリ：75% 以上
- `src/ui/` ディレクトリ：70% 以上
- 全体テストカバレッジ：70% 以上
