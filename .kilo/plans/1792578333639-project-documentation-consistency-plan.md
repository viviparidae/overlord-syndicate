# ドキュメント構造一貫性保証プラン

## 概要

ドキュメント参照の不整合を修正し、再発を防ぐ自動化チェックシステムを構築する。このプランでは以下の問題を解決する:

1. **存在しないドキュメント参照**: `docs/index.md` が参照している `docs/md-editor-plus-guide.md`
2. **非実在コンポーネント参照**: ドキュメントで参照されているが実装されていない `src/ui/CommandPanel.ts`
3. **データ型一致不備**: ドキュメントが想定している JSON データ形式と実際の TypeScript インターフェースの不一致
4. **Frontmatter 形式の不統一**: フロントマター解析に失敗する不適切なフォーマット

## 戦略的決定

### 決定1: 参照されているドキュメントは存在しない
**行動**: `docs/index.md` を更新し、`md-editor-plus-guide` へのリンクを `docs/foam-smart-folders.md` に変更します。なぜなら:
- `docs/foam-smart-folders.md` は類似のガイド（VS Code 統合）を提供し、
- `AGENTS.md §1.3` は「`docs/` 内のすべての .md ファイルを FOAM 拡張機能で管理する」とし、別々のガイドの必要性を否定し、
- `AGENTS.md §1.3` は「`docs/foam-smart-folders.md` で運用手順を記述し、`docs/index.md` から `[[wiki-link]]` を参照する」と明示的に述べているため。n
### 決定2: ドキュメントの実装コードを反映する
**行動**: 参照されているコンポーネントに置き換える:
- `src/ui/CommandPanel.ts` → `src/ui/index.ts` の `initUI()` と `setupCommandListeners()` 関数
- `src/data/dialogue/phase1.json` → `src/data/dialogue/phase1.ts` (現在は TypeScript インターフェースのみ)
- `src/data/events/phase1.json` → `src/data/events/phase1.ts` (現在は TypeScript インターフェースのみ)

理由: データは *型定義* ではなくインターフェースとして定義され、実際の JSON データは実行時にロードされる。

### 決定3: Frontmatter 形式の一貫性
**行動**: すべてのドキュメントの frontmatter 形式を正規化:
- 余分なスペースや改行を削除
- すべての必須フィールドを標準順序で含める
- オプションフィールドはトップに配置

理由: 統一された形式により、検証スクリプトの解析が安定し、人間可読性も向上する。

### 決定4: セマンティックバージョンとステータスの整合性
**行動**: すべてのドキュメントに適切なステータスとバージョンを設定:
- 初期ドキュメント: `status: draft`, `version: "0.1"`
- 承認済みドキュメント: `status: approved`, `version: "0.1"`

理由: ステータスとバージョンはプロセスの指標であり、一貫性が重要である。

## リスクと対策

### リスク1: 検証ツールの依存性
**説明**: 検証の性質が `scripts/validate-docs.mjs` に集中し、それが失敗するとすべて失敗する
**対策**: 複数のバリデーション戦略:
- CI パイプラインでの定期実行
- プレコミットフックでのローカル実行
- IDE への入力検証の統合

### リスク2: ドキュメント陳腐化
**説明**: ソースファイルが更新されてもドキュメントは更新されず、アンシンクされる
**対策**: プロセスルール:
- 仕様変更時はドキュメントを更新
- UI 変更時は関連ドキュメントをレビュー
- アクション関数変更時は `ActionResult` とドキュメントを更新

### リスク3: 依存関係チェーンの断絶
**説明**: ドキュメントが外部参照（`src/ui/`、`src/balance/` など）を誤って参照すると、すべての downstream 検証が失敗する
**対策**: 統合な依存関係グラフ:
- `src/balance/Costs.ts` から関連ドキュメントを検索
- `src/localization/index.ts` から参照されるすべてのドキュメントをリストアップ
- 各ドキュメントの `implemented_by` に依存関係をリストアップ
